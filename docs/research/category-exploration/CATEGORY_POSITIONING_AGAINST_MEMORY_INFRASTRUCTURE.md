# Category Positioning Against Memory Infrastructure

**Version:** v0.1

**Scope:** Strategy / Category Formation / Competitive Positioning  
**Runtime Authority:** None  
**Product Claim:** None  
**Public Claim Status:** Not approved for external use

## 1. Purpose

This document defines how DETERMA should compare the Verified Execution State thesis against AI memory infrastructure without creating an inaccurate claim that DETERMA is a memory company.

## 2. Core Distinction

Memory infrastructure addresses:

> What does the agent know?

Verified execution state infrastructure addresses:

> What operational state is true, verified, and action-relevant now?

Runtime authority addresses:

> Is this specific action still allowed now?

## 3. Strategic Position

DETERMA should not compete directly with memory companies on generic context compression, vector retrieval, or long-term organizational memory.

Instead, DETERMA should explore whether it can own the execution-side state layer:

- authority state
- approval state
- policy state
- environment state
- risk state
- dependency state
- execution-history state
- freshness and invalidation boundaries

## 4. Positioning Formula

Recommended framing:

> Memory reduces repeated knowledge reconstruction. DETERMA explores reducing repeated execution-state reconstruction.

Alternative framing:

> As AI agents gain better memory, execution authority and verified state become more important, not less.

Avoid:

> DETERMA is a better memory layer.

Avoid:

> DETERMA saves more tokens than memory companies.

Such claims require empirical evidence.

## 5. Comparison Table

| Dimension | Memory Infrastructure | Verified Execution State Infrastructure |
|---|---|---|
| Primary question | What does the agent know? | What is action-relevant and true now? |
| Core asset | persistent memory / retrieval / context compression | verified operational state object |
| Main cost reduced | knowledge/context loading | state reconstruction, governance reasoning, coordination |
| Typical sources | documents, messages, code, CRM, knowledge bases | policy, approvals, IAM, Git, CI, risk, runtime, execution history |
| Freshness requirement | variable | usually high |
| Security sensitivity | high | very high |
| Failure mode | wrong or missing context | unauthorized or stale execution |
| DETERMA fit | adjacent | core research expansion |

## 6. Category Boundary

The proposed category is not:

- vector database
- RAG
- long-term memory
- generic agent framework
- workflow orchestration
- traditional authorization engine

The proposed category is:

> infrastructure that compiles, verifies, bounds, signs, and serves execution-relevant operational state to agents and runtimes.

## 7. Why Memory Alone Is Insufficient

A memory system may recall that an approval existed, a policy was previously applied, or a branch had a certain state.

That does not prove:

- the approval is still valid
- the policy is still current
- the branch is unchanged
- the environment is safe
- the intended action remains within bounds
- the authority has not been revoked

Execution requires freshness, verification, and invalidation.

## 8. Why Authorization Alone Is Insufficient

Traditional authorization can return permit or deny for a request.

But agent execution often requires broader operational context:

- intent normalization
- delegated agency
- source provenance
- risk context
- execution history
- replay resistance
- stale-state detection
- multi-step workflow boundaries

The research thesis is that these may need to be compiled into a reusable execution-state primitive.

## 9. Token-Savings Positioning

Token savings should be framed as a possible secondary effect, not the primary positioning.

Acceptable internal hypothesis:

> Verified state objects may reduce token usage by replacing repeated natural-language reconstruction of policy, authority, risk, environment, and execution history.

Not acceptable as public claim without evidence:

> DETERMA saves more tokens than memory infrastructure.

## 10. External Messaging Guardrail

Until empirical validation exists, external messaging should stay at the level of:

> Memory helps agents remember. Verified execution state helps determine what they can safely and validly do now.
